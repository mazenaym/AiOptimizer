# AiOptimizer — توثيق فكرة المشروع

تاريخ المراجعة: 29 سبتمبر 2026. هذا التوثيق مبني على قراءة الكود الحالي، وليس على اختبار تشغيل الخدمة أو الاتصال بمزوّدي الذكاء الاصطناعي.

## 1. ملخص الفكرة

**AiOptimizer**، والمسمّى داخل الحل البرمجي **PromptOptimizer**، هو مشروع منصة تساعد المستخدم على كتابة تعليمات أفضل للذكاء الاصطناعي، وتنظيم هذه التعليمات والرجوع إليها. تُسمّى التعليمات التي يرسلها المستخدم إلى النموذج **Prompt**.

الفكرة المستهدفة هي استقبال Prompt أولي، ثم إعادة صياغته باستخدام نموذج ذكاء اصطناعي ليصبح أوضح في الهدف والسياق والقيود وشكل الإجابة المطلوبة. يختار المستخدم المجال والمزوّد والنموذج، ويمكنه إضافة تعليمات خاصة، ثم يحصل على صياغة محسّنة مع بيانات العملية.

المخرَج الأساسي المقصود هو **تحسين نص السؤال أو التعليمات نفسها**. مثال: تحويل طلب عام لكتابة محتوى إلى تعليمات محددة للجمهور والأسلوب والطول، ليستخدمها الشخص لاحقًا مع نموذج الذكاء الاصطناعي.

## 2. المشكلة التي يعالجها

الطلبات العامة أو الناقصة قد تنتج إجابات لا تتوافق مع احتياج المستخدم. كذلك يصعب الاحتفاظ بالصياغات الناجحة ومتابعة التجارب عند توزيعها على محادثات وأدوات متعددة.

يهدف المشروع إلى:

- توضيح المطلوب داخل الـPrompt وتقليل الغموض.
- تنظيم الـPrompts حسب المستخدم والتصنيف واللغة.
- إتاحة تجربة أكثر من مزوّد ونموذج من خلال بنية واحدة.
- الاحتفاظ بعمليات التحسين وربطها بالنص الأصلي.
- توفير أساس لمتابعة الاستهلاك والتكلفة والاشتراكات.

تحسين الجودة هنا هدف للمنتج؛ الكود الحالي لا يتضمن تقييمًا يثبت أن كل صياغة محسّنة تعطي نتائج أفضل أو تقلّل التكلفة.

## 3. المستخدمون المحتملون

هذه شرائح مقترحة لاستخدام المنتج، وليست أدوارًا منفصلة مطبّقة في النظام:

| المستخدم | الاستخدام المحتمل |
| --- | --- |
| المطوّر | صياغة طلبات توليد الكود وشرحه ومراجعته |
| كاتب المحتوى | تحديد الجمهور والنبرة والطول وشكل المخرجات |
| الطالب أو الباحث | تنظيم طلبات الشرح والتلخيص والمقارنة |
| مستخدم الذكاء الاصطناعي | الاحتفاظ بمكتبة شخصية من التعليمات وإعادة استخدامها |

## 4. مثال توضيحي

**قبل التحسين:**

> اكتب بوست عن تعلم البرمجة.

**صياغة محسّنة توضيحية:**

> تصرّف ككاتب محتوى تعليمي. اكتب منشورًا باللغة العربية موجّهًا للمبتدئين عن بدء تعلم البرمجة. استخدم أسلوبًا بسيطًا ومشجّعًا، واذكر ثلاث خطوات عملية، واجعل طول المنشور بين 150 و200 كلمة، واختم بسؤال يشجّع القارئ على المشاركة. تجنّب الوعود غير الواقعية والمصطلحات غير المشروحة.

هذا مثال لشرح الفكرة، وليس نتيجة فعلية جرى توليدها أو اختبارها داخل المشروع.

## 5. رحلة المستخدم المستهدفة

1. ينشئ المستخدم حسابًا أو يسجّل الدخول.
2. يضيف النص الأصلي، مع عنوان وتصنيف ولغة عند الحاجة.
3. يختار مزوّد الذكاء الاصطناعي والنموذج ويضيف تعليمات تخصيص اختيارية.
4. يطلب تحسين النص.
5. يراجع النص المحسّن وبيانات العملية.
6. يرجع إلى النص وعمليات التحسين السابقة ويتابع استهلاكه.

هذه رحلة المنتج المقصودة. المتاح حاليًا عبر الـAPI يغطي الحسابات وإنشاء النصوص وعرضها وحذفها وعرض التصنيفات والنماذج. بقية الرحلة تحتاج استكمال الربط والتنفيذ.

## 6. الحالة الحالية في الكود

| الجزء | الحالة الحالية |
| --- | --- |
| الحسابات | توجد أوامر ومسارات للتسجيل والدخول، مع ASP.NET Core Identity وخدمات JWT وRefresh Tokens |
| إدارة الـPrompts | إنشاء، عرض قائمة بصفحات، عرض عنصر، وحذف؛ مرتبطة بالمستخدم الحالي |
| بيانات الـPrompt | نص أصلي، عنوان اختياري، تصنيف اختياري، لغة اختيارية، وحقل IsSaved |
| التصنيفات والنماذج | توجد مسارات API لعرضها |
| محرك التحسين | موجود؛ يبني تعليمات حسب المجال والتخصيص ثم يوجّه الطلب إلى خدمة المزوّد |
| تشغيل التحسين عبر API | غير متاح حاليًا؛ OptimizePromptCommand معلّق بالكامل، ولا يوجد مسار تحسين في PromptsController |
| مزوّدو الذكاء الاصطناعي | توجد خدمات OpenRouter وGemini وOllama، لكن تسجيل تطبيقات IAIService في حقن الاعتمادات معلّق |
| سجل التحسين والاستهلاك | توجد نماذج وبنية مبدئية؛ لا توجد دورة مكتملة مفعّلة عبر API، وUsageController معلّق |
| الخطط والاشتراكات | توجد كيانات لتمثيلها؛ لا يظهر مسار API لإدارة الاشتراك أو الدفع |
| واجهة المستخدم | المستودع الذي تمت مراجعته يحتوي على Backend ومشروعات اختبارات، ولا يحتوي على واجهة Frontend |

وجود ملف أو كيان في المشروع لا يعني أن الميزة متاحة للمستخدم النهائي. كذلك خدمة Refresh Token موجودة، لكن AuthController الحالي يعرض التسجيل والدخول فقط.

## 7. كيف صُمّم التحسين؟

يستقبل `PromptOptimizerEngine` النص والمجال ومزوّد النموذج ومفتاح النموذج والتعليمات الاختيارية. يكوّن تعليمات تطلب تحسين الجودة والوضوح والدقة، ثم يستخدم `AIServiceFactory` للوصول إلى خدمة المزوّد.

الاستجابة البرمجية مصممة لحمل النص المحسّن، وشرح، واستهلاك Tokens، وزمن التنفيذ. الـToken وحدة يعالج بها النموذج النص، وليست بالضرورة كلمة كاملة.

توجد قيود مهمة في التنفيذ الحالي:

- خدمات OpenRouter وGemini تُرجع نصوصًا تجريبية عند غياب مفتاح API.
- خدمة Ollama تُرجع بديلًا نصيًا عند حدوث خطأ في الاستدعاء.
- أعداد Tokens في Gemini وOllama ثابتة داخل الكود، وليست قياسًا فعليًا للاستهلاك. OpenRouter يقرأ الاستهلاك من استجابة المزوّد عند الاتصال الحقيقي.
- الشرح المُعاد من الخدمات عبارة عن وصف ثابت، وليس تحليلًا تفصيليًا للتغييرات التي أجراها النموذج.

لذلك لا ينبغي تقديم هذه البدائل أو الأرقام للمستخدم باعتبارها نتائج تحسين فعلية أو بيانات محاسبية دقيقة.

## 8. البنية التقنية

المشروع مكتوب بلغة C# ويستهدف .NET 10، ومقسّم إلى أربع طبقات:

| الطبقة | المسؤولية |
| --- | --- |
| PromptOptimizer.Domain | كيانات المشروع وعلاقاتها، مثل Prompt وOptimization وAIModel وSubscription |
| PromptOptimizer.Application | حالات الاستخدام والأوامر والاستعلامات والتحقق من المدخلات ومحرك التحسين |
| PromptOptimizer.Infrastructure | قاعدة البيانات والمصادقة وخدمات الاتصال بمزوّدي الذكاء الاصطناعي |
| PromptOptimizer.Api | مسارات HTTP وتحديد المستخدم الحالي ومعالجة الأخطاء وتسجيل الطلبات |

التقنيات المستخدمة في الكود تشمل ASP.NET Core Web API، وEntity Framework Core مع PostgreSQL عبر Npgsql، وMediatR، وFluentValidation، وASP.NET Core Identity، وJWT، وSwagger في بيئة التطوير.

يوجد حد للطلبات داخل الذاكرة يبلغ 60 طلبًا في الدقيقة لكل عنوان IP. كما توجد ملفات للكاش وعدّ Tokens، لكن تسجيل خدمات Redis وعدّ Tokens معلّق في الإعداد الحالي.

## 9. نموذج البيانات المفاهيمي

| الكيان | الغرض |
| --- | --- |
| ApplicationUser | حساب المستخدم |
| Prompt | النص الأصلي ومعلومات تنظيمه ومالكه |
| PromptCategory | تصنيف النص |
| Optimization | تمثيل عملية تحسين مرتبطة بنص |
| AIProvider وAIModel | تمثيل المزوّد والنموذج المستخدم |
| UsageRecord | تمثيل استهلاك عملية التحسين |
| Plan وSubscription | تمثيل الخطة واشتراك المستخدم وحدود الاستخدام |
| PromptTemplate | تمثيل قالب Prompt قابل لإعادة الاستخدام |
| RefreshToken | دعم جلسات المصادقة من خلال رموز التجديد |

العلاقة المحورية هي أن المستخدم يملك نصوصًا، ويمكن لكل نص أن يرتبط بعدة عمليات تحسين. هذا يسمح مستقبلًا بمراجعة التجارب المختلفة على النص نفسه. بعض هذه الكيانات تمثّل أساسًا لميزات لم تكتمل بعد.

## 10. المسارات المتاحة في الـAPI

| الطريقة | المسار | الغرض |
| --- | --- | --- |
| POST | `/api/auth/register` | إنشاء حساب |
| POST | `/api/auth/login` | تسجيل الدخول |
| POST | `/api/prompts` | إنشاء Prompt |
| GET | `/api/prompts` | عرض قائمة النصوص مع pageNumber وpageSize |
| GET | `/api/prompts/{id}` | عرض نص محدد |
| DELETE | `/api/prompts/{id}` | حذف نص محدد |
| GET | `/api/categories` | عرض التصنيفات |
| GET | `/api/models` | عرض النماذج |
| GET | `/api/health` | استجابة بسيطة عن حالة التطبيق |

مسارات النصوص والتصنيفات والنماذج تتطلب المصادقة. مسار Health لا ينفّذ فحصًا شاملًا لقاعدة البيانات أو خدمات الذكاء الاصطناعي.

مثال جسم طلب إنشاء Prompt، بعد تسجيل الدخول وإرسال Access Token:

```json
{
  "originalContent": "اكتب بوست عن تعلم البرمجة",
  "title": "منشور تعليمي",
  "categoryId": null,
  "language": "ar"
}
```

الإنشاء يخزّن النص في قاعدة البيانات ويضبط `IsSaved` على `false`. لا يستدعي نموذج ذكاء اصطناعي ولا ينفّذ تحسينًا تلقائيًا. حقل النص إلزامي وبحد أقصى 10,000 حرف، والعنوان حتى 255 حرفًا، واللغة حتى 20 حرفًا.

## 11. نطاق مقترح لأول نسخة قابلة للاستخدام

الأولويات التالية مقترحة بناءً على الفجوة بين فكرة المنتج والتنفيذ الحالي:

1. استكمال أمر التحسين ليتوافق مع الكيانات الحالية، وإتاحته عبر API.
2. تفعيل تسجيل خدمات المزوّدين والتحقق من إعداداتها ومعالجة فشل الاتصال بوضوح.
3. حفظ نتيجة التحسين وربطها بالنص والمستخدم والنموذج، وإتاحة عرض سجل العمليات.
4. بناء واجهة تعرض النص الأصلي والمحسّن وتتيح نسخ النتيجة.
5. استخدام بيانات استهلاك فعلية أو تمييز التقديرات بوضوح قبل عرض التكلفة.
6. اختبار رحلة متكاملة من الدخول إلى التحسين والحفظ واسترجاع النتيجة.

بعد اكتمال الرحلة الأساسية يمكن إضافة مكتبة قوالب، ومقارنة نتائج النماذج، ولوحة استهلاك، وخطط اشتراك. هذه توسعات مقترحة وليست ميزات مكتملة حاليًا.

## 12. وصف مختصر جاهز للعرض

> AiOptimizer هو مشروع منصة لتحسين وإدارة التعليمات الموجّهة إلى نماذج الذكاء الاصطناعي. يهدف إلى تحويل الطلبات الأولية إلى صياغات أوضح وأكثر تحديدًا، مع دعم مزوّدين متعددين وتنظيم النصوص ومتابعة عمليات التحسين والاستهلاك. النسخة الحالية توفّر أساس الـBackend للحسابات وإدارة النصوص والتصنيفات والنماذج، بينما يحتاج مسار التحسين الكامل وواجهة المستخدم إلى الاستكمال.

- `src/PromptOptimizer.Api/Controllers/`: المسارات المتاحة حاليًا.

- `src/PromptOptimizer.Application/Prompts/Commands/OptimizePrompt/OptimizePromptCommand.cs`: أمر التحسين المعلّق.
- `src/PromptOptimizer.Application/Optimization/Services/PromptOptimizerEngine.cs`: منطق توجيه التحسين.
- `src/PromptOptimizer.Infrastructure/AI/`: خدمات المزوّدين وسلوك الاستجابات البديلة.
- `src/PromptOptimizer.Infrastructure/DependencyInjection.cs`: إعداد قاعدة البيانات وتسجيل الخدمات.
- `src/PromptOptimizer.Domain/Entities/`: كيانات المشروع.
